# ITERATION-03 Intent Context

This file is the context anchor for `ITER-03`.  
It explains what we are trying to achieve and how the current iteration should run end-to-end.

## Layer 1: Executive Summary

### Зачем эта итерация
Собрать разрозненный корпус знаний из `raw-exports` в управляемый, проверяемый и переиспользуемый слой знаний.  
Фокус `ITER-03`: сначала целостная первичная дистилляция, затем нарезка на смысловые слайсы, затем точечная передистилляция и структурирование в устойчивые артефакты.

### Что на выходе
- Полный first pass по источникам из `PRIMARY_PASS_REGISTRY.md`.
- Набор первичных заметок в `docs/research/distillation/primary-notes/<SOURCE_ID>.md`.
- Карта контекстных слайсов в `docs/research/distillation/CONTEXT_SLICE_MAP.md`.
- Очередь точечных задач передистилляции в `docs/research/distillation/TARGETED_REDISTILL_BACKLOG.md`.
- Подготовленная база для следующей итерации (`ITER-04`) с узкими, хорошо ограниченными задачами.

### Критерий успеха
- Любой `SOURCE_ID` можно быстро проследить от raw-источника до distilled-claims.
- Вся повторяющаяся информация сгруппирована в явные `SLICE-XXXX`.
- Backlog передистилляции содержит только конкретные, выполнимые задачи с ожидаемым выходом.
- Другой агент может продолжить процесс без восстановления контекста "с нуля".

### Что не делаем в этой итерации (anti-goals)
- Не редактируем содержимое raw-транскриптов в `raw-exports`.
- Не меняем действующие ID-контракты (`CHAT-*`, `PXXXX`, `SLICE-XXXX`, `REDIST-XXXX`, `US/UC/NFR/AT/ADR`).
- Не пытаемся финализировать всю продуктовую документацию за один проход.
- Не подменяем evidence интерпретацией без ссылок на источник.

### Связь с ITER-04
`ITER-03` формирует "операционное ядро контекста": очищенные claims, слайсы и приоритетный backlog.  
`ITER-04` использует это ядро для глубокой, точечной передистилляции по отдельным доменам/решениям с более строгими критериями качества.

## Layer 2: Operational Intent

### Входные источники
- `CHAT_REGISTRY.md` (основной корпус iteration-01/02).
- `CHAT_REGISTRY_ITERATION_00.md` (legacy prehistory корпус).
- `Harring.md` (выделенные harness engineering цитаты).
- `docs/research/artifacts/**/*` (truth zone для стандартов и viewpoints).

### Конвейер работ
1. Выполнить primary distillation по порядку `PRIMARY_PASS_REGISTRY.md`.
2. Для каждого источника зафиксировать `intent`, `atomic_claims`, `stable/volatile` и риски в `primary-notes`.
3. Агрегировать повторяемые claims в `CONTEXT_SLICE_MAP.md`.
4. Сформировать узкие задачи в `TARGETED_REDISTILL_BACKLOG.md` с ожидаемыми артефактами.
5. Выпускать структурированные artifacts по слайсам только после явной трассировки на источники.

### Правила нарезки (context slicing)
- Нарезать по смысловым доменам и вопросу использования, а не по объему исходных файлов.
- Каждый слайс обязан иметь явные `source_ids` и evidence refs (`source_path:line`).
- Один claim может входить в несколько слайсов только с разными целями применения.
- При конфликте трактовок сохранять ambiguity в явном виде, не "склеивать" насильно.

### Правила повторной дистилляции (targeted redistillation)
- Каждая задача `REDIST-XXXX` должна быть узкой: конкретный вопрос, ограниченный `source_subset`, фиксированный `expected_output`.
- Передистилляция запускается после накопления достаточного первичного материала по связанным слайсам.
- Результат передистилляции должен уменьшать неопределенность, а не увеличивать объем пересказа.

### Качество и контроль
- Traceability: каждый важный claim имеет ссылку на `source_path:line`.
- Разделение на `stable_knowledge` и `volatile_knowledge` обязательно в первичных заметках.
- Все ambiguities, corruption-маркеры и unsupported-фрагменты фиксируются как quality risks.
- Любое структурирование в `docs/` опирается на evidence и не нарушает source-of-truth иерархию.

### Definition of Done (intent cycle)
- Layer 1 читается за 2-3 минуты и дает полную картину цели итерации.
- Layer 2 достаточно детален, чтобы другой агент продолжил работу без принятия новых архитектурных решений.
- Процесс дистилляции, нарезки и передистилляции согласован с `ITERATION_LEDGER` и текущими реестрами.
